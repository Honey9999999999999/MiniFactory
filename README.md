# Тестовое задание: Mini Factory

Проект представляет собой инкрементальный симулятор фабрики (кликер/idle) с автоматической генерацией валюты, системой улучшений, временными бустами, оффлайн-прогрессом и интеграцией внутриигровых покупок (IAP).

---

## 🚀 Инструкции по запуску и Android Build

### Запуск в Unity Editor
1. Установите **Unity 6000.3.22f1** через Unity Hub.
2. Склонируйте репозиторий и откройте проект в Unity.
3. Откройте сцену `Assets/FactoryProject/Scenes/MainFactory.unity`.
4. Нажмите кнопку **Play**. 
   * Для тестирования IAP в редакторе автоматически активируется **Fake Store**. При нажатии на кнопку покупки всплывет системное диалоговое окно Unity, где нужно нажать **Succeed** для эмуляции успешной транзакции.

### Сборка Android Build (.apk)
1. Перейдите в **File ➔ Build Profiles** (или *Build Settings*).
2. Убедитесь, что выбран профиль платформы **Android**. Если нет — нажмите **Switch Platform**.
3. Проверьте, что сцена `MainFactory` добавлена в список *Scenes in Build*.
4. Нажмите кнопку **Build** и сохраните `.apk` файл.
5. Установите полученный файл на устройство или эмулятор. При первом запуске на устройстве Unity IAP также будет автоматически использовать защищенную песочницу (Fake Store), так как билд не подписан релизным ключом Google Play.

## 🏗️ Описание основных систем и архитектурных решений

* **Слой Данных (Data) & Сохранения:** Классы `PlayerSaveData` и `MachineState` представляют собой чистые C#-модели данных. Сохранение состояния между сессиями реализовано через JSON-сериализацию в `PlayerPrefs`. Для защиты от поломки данных сохранение триггерится автоматически в методах `OnApplicationPause` и `OnApplicationQuit`.
* **Игровая Логика (Core):** Компонент `FactoryManager` инкапсулирует всю математику игры (расчет экспоненциального роста стоимости улучшений, производительности машин и тайм-менеджмент буста). Менеджер полностью автономен и ничего не знает про интерфейс. Связь с UI построена на C#-событиях (`event Action OnDataChanged`), что исключает лишний `Update`-поллинг данных.
* **Конфигурация (Scriptable Objects):** Все экономические параметры и баланс вынесены в `GameConfig` (Scriptable Object). Логика защищена интерфейсом `IGameConfig`. Это позволяет в будущем бесшовно заменить или дополнить локальный конфиг системой **Remote Config** без изменения кодовой базы игры.
* **Изоляция SDK (IAP и Аналитика):** Игровая логика полностью защищена от изменений внешних API с помощью инверсии зависимостей. Unity IAP v5 и система аналитики закрыты интерфейсами `IIapService` и `IAnalyticsService`.
* **Система Аналитики:** Реализована через паттерн **Composite**. Главный `AnalyticsManager` транслирует вызовы во все зарегистрированные провайдеры. В проекте реализован обязательный `DebugAnalyticsProvider`, который красиво форматирует и логирует все требуемые по ТЗ события (включая экономические циклы и статусы IAP) в консоль Unity.
* **Юнит-тестирование:** Написаны EditMode-тесты (`FactoryCoreTests`) на базе NUnit, проверяющие три критических сценария экономики в изоляции: расчет базового производства, прогрессию стоимости апгрейдов и логику блокировки при нехватке средств.

## 📦 Использованные Packages / SDK

Проект использует минимальный и чистый набор официальных пакетов Unity, прописанных в `manifest.json`:
* **In-App Purchasing (v5.x)** — актуальная версия официального пакета Unity для работы с покупками через новое асинхронное событийно-ориентированное API.
* **TextMesh Pro** — для высококачественного отображения текстовых элементов UI.
* **Unity Test Framework** — для интеграции NUnit и запуска юнит-тестов через Test Runner.

## 🔍 Известные ограничения или незавершенные части

* **Визуальная верстка:** UI реализован в виде схематичного тестового HUD для демонстрации полной работоспособности кода, систем и архитектурных связей (согласно ТЗ, фокус сделан на кодовой базе).
* **Локализация:** Строки в UI зашиты на русском языке. Архитектура готова к внедрению пакета *Unity Localization*, но в текущей итерации он не подключался.
* **Валидация времени:** Оффлайн-прогресс и буст рассчитываются на основе локального системного времени устройства (`DateTime.UtcNow`). Для коммерческого продакшена расчет времени необходимо перенести на валидацию через защищенный сетевой NTP-сервер для предотвращения читерства переводом часов.

## ⏱️ Примерное фактическое время работы
Общее чистое время разработки составило около **6 часов**, распределенных следующим образом:
* **Архитектура и Core-логика (2.5 часа):** Проектирование связей, написание менеджера фабрики, формул экономики и логики оффлайн-прогресса.
* **Интеграция Unity IAP v5 (1.5 часа):** Адаптация кода под актуальные асинхронные стандарты IAP v5, изоляция Purchasing API интерфейсами, отладка симуляции в Fake Store.
* **Аналитика и Тесты (1 час):** Создание композитного сервиса логирования, отладка форматированного вывода словарей параметров в консоль, написание и запуск EditMode юнит-тестов.
* **UI и Рутина (1 час):** Сборка тестовой сцены, связывание UI-компонентов с событиями фабрики, чистка проекта от мусора, настройка `.gitignore` и сборка финального Android-билда.

## 🛠️ Что осталось незавершенным
* **Интеграция с реальными SDK Аналитики:** В коде создана идеальная архитектурная база (паттерн *Composite*), но реальные провайдеры (например, AppMetrica SDK или Firebase) не подключались — вся отправка перехвачена Debug-провайдером.
* **Защита оффлайн-времени от читерства:** Начисление валюты за время отсутствия работает на основе локальных часов устройства (`DateTime.UtcNow`). Игрок может искусственно ускорить прогресс, просто переведя время в настройках Android.
* **Полноценный UI/UX и Анимации:** Интерфейс остался на уровне базового «серого» прототипа без использования анимаций (например, всплывающих цифр дохода `+X` над машинами или плавного заполнения слайдеров буста).

## 🚀 Что я сделал бы следующим шагом
1. **Внедрение DI-контейнера (Zenject / VContainer):** Для еще более элегантного и чистого связывания фабрики, IAP и аналитики. Это позволит избавиться от рефлексии в юнит-тестах при подмене Mock-конфигов.
2. **Серверная валидация времени:** Подключение легковесного API для запроса точного времени с доверенного сетевого сервера (NTP) при сворачивании/разворачивании игры, чтобы полностью исключить уязвимость оффлайн-прогресса к манипуляциям с часами телефона.
3. **Пул объектов (Object Pooling) для UI-эффектов:** Создание системы пулирования для Floating Text (всплывающих цифр дохода), чтобы при высокой скорости генерации валюты сотни текстовых элементов не нагружали процессор (CPU) частыми вызовами `Instantiate` и `Destroy`.
4. **Визуальное улучшение UI:** Перевод интерфейса на современный **UI Toolkit** (если требуется по стандартам студии) или интеграция пакета *DOTween* для создания сочных анимаций кликов, апгрейдов и пульсации кнопок во время активного Буста.
